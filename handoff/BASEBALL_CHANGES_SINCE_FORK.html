The release is one feature with a lot of surface area: recent form. Season percentiles answer “how good has this player been”; nothing in the app answered “what is he doing right now”. Adding that meant a new backend table, a new tab, new controls, and a pass over every screen that shows a number. Roughly half the diff is the recent-form feature, a quarter is the design-system cleanup it forced, and a quarter is monetization and review-funnel fixes.

1Rolling-window data pipeline

Per-game metric expansion

ingest_game_logs.py previously wrote a thin per-game row off the terminal pitch of each plate appearance. It now does a second, pitch-level pass and stores far more:

  • Pitch-level rates (Whiff%, Chase%) — these can’t be derived from the terminal-PA frame, since most whiffs happen on pitches that don’t end the PA. Separate groupby over every pitch in the chunk, keyed (player_id, game_date) and joined back.
  • Swing tracking (bat speed, swing length) averaged over swings only, not over all pitches.
  • Fastball-only velo and spin (FF/SI/FC). Averaging every pitch drags a starter’s number down with his changeup, so it couldn’t be placed on the season Fastball Velo ruler. Also stores _fb_pitches as the denominator — without it, velo/spin silently drop out of the rollup (that was a shipped bug, fixed in c0ca144).
  • Traditional counting stats stored as raw underscore-prefixed counts (_ab, _h, _2b, _3b, _hr, _tb, _bb, _so, _hbp, _sf) rather than as rates, so the rollup can derive an exact window AVG/OBP/SLG from sums. Averaging per-game batting averages weights an 0-for-1 like a 4-for-4.
  • Savant-correct expected stats: xBA/xSLG denominators are at-bats with strikeouts counted as an 0-for (Statcast leaves those columns null on non-batted-balls, so a plain mean drops strikeouts and inflates everything); xwOBA is sum(xwOBA value) / sum(wOBA denominator).
Rule that made all of it work: store numerators and denominators, never pre-divided rates. Every window figure is then recomputed exactly rather than approximated.

New table: player_recent_form

primary key (player_id, season, player_type, window_days)
as_of date, team, games, plate_appearances, batted_ball_events
metrics jsonb, prior_metrics jsonb, delta jsonb

Shape is Savant’s rolling leaderboard: NOW / THEN / delta. metrics is the window ending on the latest game date, prior_metrics the equal-length window immediately before it, delta the change. Metrics stay in jsonb so the metric set evolves without a migration. Three indexes: leaderboard (season, window_days, player_type), profile (player_id, season), team (season, window_days, team). RLS on, public read.

Why pre-aggregate at all: a league-wide 30-day slice of player_game_logs is ~9,700 rows / ~2.4 MB that the client would have to download and aggregate before it could sort anything. The rollup is ~1,100 rows per window, ~440 KB, one fetch.

rollup_recent_form.py

New script, 390 lines. Reads game logs, writes the three windows (7 / 15 / 30 days). The important part is the WEIGHTS map: each rate metric declares which stored denominator it’s a rate of (xwoba → _woba_denom, batted-ball rates → _bbe, whiff/bat speed → _swings, chase → _oz_pitches, fastball shape → _fb_pitches, K%/BB% → _pa). Aggregating as sum(rate × denom) / sum(denom) reproduces sum(num)/sum(denom) exactly. Peaks (max EV) take the max, not a weighted mean. A metric with no data in a window is omitted rather than zeroed, and the client drops nulls to match.

Workflow changes

  • Two nightly crons instead of one: 30 8 * * * (early pass, ~2.5 h after the last west-coast game) and 0 14 * * * (backstop). A single early run is what the workflow originally had and it broke the app — Savant hadn’t published the previous night, so every run returned nothing new and the app permanently read “Through <two days ago>”. Upserts are idempotent, so the early pass wins when the source is prompt and the late pass catches the nights it isn’t.
  • workflow_dispatch input full_game_log_reingest → ingest_game_logs.py --full. A metric-set change only reaches already-ingested games via a full re-ingest; the nightly path stays incremental. Timeout raised 30 → 90 min for that path.
  • New rollup step after game-log ingest.

2Recent-form client layer

  • RecentForm.swift — model mirroring the table. Two things worth copying: as_of is a Postgres date, so it arrives as "YYYY-MM-DD" and will not parse with the ISO8601 strategy the rest of the payload uses (hand-parsed); and nulls in the metric dictionaries are dropped rather than coerced to zero. isSmallSample gates the UI at <15 PA (batters) / <30 (pitchers).
  • TrendMetric.swift — the metric catalogue for the Trends board, keyed to rollup columns rather than season labels. Carries unit, decimals, and crucially lowerIsBetter, so a pitcher’s opponent-xwOBA and a hitter’s chase rate rank the right way round. Split into batting/pitching × statcast/standard.
  • RecentMetricKey — one shared season-label → rollup-key mapping plus the one value formatter. The leaderboard, team roster and team cards had each grown a private copy, which is how a metric ends up trending on one screen and blank on the next.
  • StatcastAPI.fetchRecentForm(season:windowDays:) — paged fetch, cache-bypassing, with a lossy element decoder so one malformed row can’t empty the board.
  • DashboardViewModel — recentFormByWindow: [Int: [Int: RecentForm]] cached per window so flipping 7/15/30 doesn’t refetch, plus recentWindow, showingRecent, recentFormAsOf (for honest “through Jul 24” labelling), and per-window loading/error state.

3Trends tab (hot / cold board)

New fourth tab, HotColdView.swift (514 lines). Ranks the league by change, not level: a .380 xwOBA is interesting, a .380 that was .250 a fortnight ago is the thing season totals can’t tell you.

  • Controls: Hitting / Pitching side, Advanced / Standard stat mode, a metric menu narrowed by that mode, a 7/15/30 window, and Heating / Cooling direction. Direction is the only control that colours itself (flame red / snowflake blue); rows use the normal percentile gradient.
  • Ranking is on improvement (lowerIsBetter ? -delta : delta), so “heating up” means the same thing on both sides of the ball.
  • Small samples are excluded outright — a 3-PA week produces enormous deltas that crowd out every real riser.
  • The board is purely league-wide. An earlier build wedged a personal “Your players” section above it; that made one tab answer two questions and buried the leaderboard the subscription is sold on. Followed players are now just starred inline, and the personal list lives on Compare.
  • Locked state is a fixed, non-scrolling page. It used to share a ScrollView with the Pro board, so its height was whatever twelve invented rows added up to — short of the viewport on a big phone, leaving the unlock panel floating in grey. There is nothing below the fold to scroll to when the rows are a teaser.
Football port Direct. TrendSide becomes position group (QB / RB / WR / TE / DEF) rather than a two-way switch, which means the side control has to be a menu or a scrolling segmented row, not four inline segments. Small-sample gate becomes snaps/plays or touches rather than PA.

4Following players

FavoritesStore is a new @Observable singleton over UserDefaults holding both followed player IDs and the favorite team — previously the team lived in one place and there was no player concept at all. Insertion-ordered (a Set reshuffles “Your players” on every launch). Reuses the existing favoriteTeam key so existing favorites survive the upgrade.

FollowPlayersSheet is the bulk manager: search the league, tap to follow. Reachable from the Compare tab, which owns the followed list.

Deliberate: following is free. It’s the signal the Trends board and the review funnel both read from, so gating it would suppress the exact behaviour we most want. What’s paid is the payoff — deltas on the players you follow.

5Player profile rework

  • Season / Recent / Both segmented mode on the percentile card. Shown to everyone — a free user has to see that Recent exists before there’s anything to want — with locked segments carrying a crown and pitching on tap instead of switching.
  • Recent bars on every metric that has a season ruler. The window value is drawn on the league’s season percentile curve, which means a metric only gets a recent bar if Savant publishes a season percentile for it. That’s why batter Hard-Hit%/Sweet-Spot%/LA and pitcher Whiff%/Chase% have no recent bar even though the game logs now carry them.
  • Standard Stats tab is percentile-mapped — Savant publishes percentiles for Statcast metrics but not the traditional line, so the app computes them from the league distribution, returns nil below a usable pool size, and inverts per-side (a batter’s SO is bad, a pitcher’s is the point; a pitcher’s HR/R/BB are things surrendered). Counting stats are grouped separately and captioned as volume, since ranking them is playing-time driven.
  • Recent windows on the Standard tab, derived from the rollup’s summed counts. RBI, runs, SB and CS aren’t recoverable from pitch-level data and stay season-only.
  • Drill-downs carry the season. MetricRoute/StandardStatRoute gained a season field — tapping K% on a 2024 profile used to open the current-season leaderboard.
  • Trend arrows have a noise floor: below half of the last displayed digit (.005 / 0.05 / 0.5) no arrow is drawn, because an arrow implies a signal.
  • Trend columns are never blurred. Where the trend is a paid feature the column is simply absent — a smeared number on the main leaderboard read as broken data, not as a locked feature. The pitch lives on the controls that open the feature, not on top of the numbers.

6Teams rework

  • Division grid: six divisions of five, in standings order, all thirty clubs on one screen with no scrolling. It’s how people already hold the league in their heads, so it reads faster than an alphabetical wall even before the space saving.
  • Condensed team page with a “Both” mode (hitting + pitching at once) and roster split by side.
  • TeamStandardCard (new, 554 lines): the traditional team line percentile-mapped against the other 29 clubs, not the several hundred players. Team rates are computed from summed roster counts with a per-stat weight map (AVG/SLG → AB, OBP/OPS → PA, ERA/WHIP/K9/BB9 → IP, K%/BB% → BF) — averaging players’ averages would weight a September call-up’s 1-for-2 like a regular’s season.
  • Season / Recent windows on team cards, fed by team-scoped game-log fetches.
  • Fix: team form counted rows instead of games (every player-game row inflated the count) and anchored its window to today rather than to the last date in the data.

7One control vocabulary design system

Adding Trends exposed that same-level choices were being drawn four different ways — large filled rounded-rects, tall capsules, short capsules, underlined text tabs — at six different heights (26, 28, 30, 32, 34, 44). Two pickers that mean the same kind of thing looked unrelated. The app now keeps exactly four tiers:

TierControlUsed for
Page-level switchlarge filled rounded-rect rowPercentiles / Roster / Year Compare — “which screen is this”
Metric categorySavantTabs, underlined textHitting / Pitching / Fielding / Running (matches Savant’s own tabs)
Inline optionsSavantSegmented2–4 options: Season/Recent/Both, 7/15/30, Heating/Cooling
StandaloneSavantChipsort, search, Filters, anything opening a menu

All of them are SavantControl.height = 32. Wording is shared too: a rolling window is always “Last 15”, never “15d” on one screen and “Last 15” on the next. Segments can be individually locked — a crown, and the tap routes to the pitch instead of selecting, so a free user can see the feature exists.

Native menus only

Past four options, everything hands off to a plain SwiftUI Menu. There was an intermediate build with a hand-rolled VerticalOptionPopover (to get a narrow column of four-character years instead of UIKit’s wide menu minimum). It was reverted: it clipped its last row, opened without the system animation, and half the app’s choosers were Menus anyway, so two shapes sat a tap apart and looked like different apps. Width was the wrong thing to optimise for.

Two non-obvious fixes came with that: .menuOrder(.fixed) (UIKit reverses arrays for menus that open upward) and savantMenuAppearance(), which forces colorScheme: .light — a menu presented from a toolbar item inherits the nav bar’s .toolbarColorScheme(.dark), so the season picker opened as a black panel while the identical Filters menu a row below opened white.

SavantNavPill (red, on the navy bar) and SavantInlinePill (outlined, on a card) are the two shared trigger labels. fixedSize() on the nav pill is load-bearing: without it the toolbar squeezes the label and the title is the first thing clipped, leaving a bare icon.

8Floating tab bar & settings gear

  • Hand-rolled tab bar replacing TabView. On iOS 26 a TabView always draws its own Liquid Glass platter and .toolbarBackground(.hidden, for: .tabBar) is a no-op against it, which is what made the bar read as a grey box on the canvas. Owning the bar means there’s no system background to fight. Tabs live in a ZStack and toggle visibility so navigation stacks and scroll positions survive switching — and inactive tabs are hidden from VoiceOver too, since at opacity(0) they’re still reachable via the rotor.
  • Settings gear in the trailing toolbar, shared by all three home tabs. Settings was previously only reachable from a link under the bottom of the leaderboard, which nobody scrolls to. Trailing, because Stats already owns the leading slot with its season pill. Outline cog, no filled disc — the Liquid Glass container was giving it a pale blue circle that made a secondary control louder than the upgrade CTA. The sheet flag is owned per tab, not shared, or it pushes Settings onto all three stacks at once.

9One-tap purchase

The biggest conversion fix in the release. Every surface that named an offer (“Start 7-day free trial”) used to hand off to another screen showing the same offer under another button, so a user who had already said yes had to say it again before Apple’s confirm sheet appeared.

  • StoreService.purchaseYearlyDirect() → DirectPurchaseOutcome { unlocked, pending, cancelled, failed(String), needsPlanPicker }. .needsPlanPicker is the only case allowed to open PaywallView — it means the offering never loaded, so the picker’s retry/empty state is the honest answer. Everything else is handled in place.
  • UpgradeButton is now the app’s single conversion control, in a compact pill variant (bottom of a blurred teaser) and a full-width bar variant (card/sheet footer). The plan picker survives as a quiet “See all plans” text link, not a toll gate.
  • TrialPitchSheet rebuilt as a compact native half-sheet: names what the user just reached for, three promises, buys in place. It was a scrolling page with an 84pt hero, headline, subtitle and five two-line benefit rows — on a phone the pitch and the button were never on screen together.
  • New PaywallTrigger.lockedSeason(Int): naming the year someone reached for (“Unlock 2019”) converts better than a generic “unlock more”.
  • Season menus now list every year the dataset covers (2015→), with locked ones crowned. They used to derive from loaded histories, so a free user opened the picker, saw one year plus a generic “past seasons require StatScout+” row, and the thing being sold was invisible.
  • Paywall benefit list refreshed — it predated Trends and the team windows, so the pitch was selling less than the product does.
  • RevenueCat is now isolated from the simulator (configureIfNeeded() returns false there, purchases throw a typed error) with a STATSCOUT_FORCE_PRO=1 env override so paid surfaces are still testable headless.

10Review funnel fixes

Both repos share ReviewPromptTracker, so these are straight bugs in the football copy too:

  • Distinct-day counter. The old trigger fired on the third player profile opened, which a single sitting satisfies and which says nothing about whether anyone values the app. Now requires minimumDistinctUseDays = 3 separate calendar days (local calendar, built from DateComponents — a cached formatter isn’t Sendable under Swift 6 strict concurrency).
  • Soft defer, 30-day cooldown. Apple’s requestReview() is rate-limited and silently shows nothing much of the time, so the common case was a user who never saw a prompt being locked out for the full 120 days. “Maybe later” now sets isSoftDeferred and a 30-day cooldown.
  • The leak: the sheet’s onDismiss called markShown() unconditionally, which cleared the soft-defer flag and reinstated the full cooldown — exactly the case the soft defer exists to prevent. Now guarded on !ReviewPromptTracker.isSoftDeferred.
  • FavoritesStore.hasAnyFavorite is a new eligibility signal: someone who has curated a list has told you they’re invested, which is a better signal than page opens.

11Onboarding, metadata, misc

  • Onboarding’s primary red button is pinned to an identical Y on every page with a reserved status slot, so the thumb target never shifts; “Get Started” is quiet and borderless so the trial CTA is the loud one.
  • Leaderboard position filter (groups first — infield / outfield — then individual spots), hidden on pitching boards where every player is a P, and offering only filters that would leave something on the board.
  • Search now surfaces matching clubs, so typing “mariners” can open Seattle’s page rather than only filtering the board.
  • Payload slimming: duplicate metric fields dropped from the snapshot response.
  • fastlane/metadata/en-US/description.txt: em dashes replaced with commas/colons throughout.
  • Swift test fixtures refreshed for the new DashboardViewModel shape; new Python tests for game logs and the rollup.

Gotchas worth reading twice

  • Store denominators alongside every rate, or the window can’t be recomputed exactly — and a missing denominator makes the metric vanish from recent form silently (that shipped once).
  • A metric-set change reaches old rows only via a full re-ingest. Wire the manual-dispatch flag at the same time as the metric change, not after.
  • Omit metrics with no data in a window; never zero them. Client drops nulls to match.
  • A recent value has no percentile of its own. Draw it on the season ruler, and only for metrics that have one — otherwise it’s uncoloured ink.
  • Never blur real numbers to sell a feature. Absent column + a pitch on the control that opens it.
  • Locked/teaser states must fill the viewport. A teaser inside a ScrollView ends mid-screen on a large phone.
  • Anchor rolling windows to the last date in the data, not to today, and label them with as_of.
